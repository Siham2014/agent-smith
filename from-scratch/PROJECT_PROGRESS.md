### Workflow and guarantees

START → Generate → Extract → Verify → Decide → Revision or Finalize → END.
The default Gemini path reuses the existing GeminiProvider and one client.
Injected providers are caller-owned and bypass local configuration completely.
Both paths use the normalized Phase 2 LLMRequest/LLMResponse contract.

State validates a nonblank task, strict budget 1–2, nonnegative counts/times,
consecutive history and matching observations/code. A generating state can
temporarily have one in-flight call; terminal history must account for all calls.
Input contract violations raise validation errors before client creation.
Controlled provider/runtime failures return a structured failed result.

Count before provider.generate. Never more than two calls, never a transport
retry, never a model-based self-evaluation. A first syntax pass stops immediately
as unverified/syntax_passed_functionality_unverified. Only unusable output or a
syntax error can consume a remaining revision call. Fatal access/configuration/
quota/network/timeout errors stop immediately with stable reasons.

Raw Python or one correctly closed Python/py Markdown block is accepted.
Empty, ambiguous and malformed fences are rejected.
AST checks only syntax. No execution, imports from generated code, runtime tests
or functional proof. Responses are bounded to 100000 characters before parsing;
diagnostics are bounded line/column messages without source echoes.
This is not a sandbox or a hard resource deadline.

Successful attempts preserve SDK-call latency and returned token counts.
Failed calls use measured elapsed duration without fabricated tokens.
Total latency measures the workflow including owned-client cleanup.
Only fully known token fields are summed across attempts; partial data remains
available in history while incomplete totals remain None.
